# Token and Handoff-Quality Benchmark Methodology

> The manual for `scripts/kb-benchmark.py`. It answers three questions:
> how many tokens were saved, whether the saving is honest, and whether the number may be quoted externally.

Chinese edition: `benchmark.zh-CN.md`.

## 0. In one line

Ten fixed tasks, one library, comparing the **context size** and **answer correctness** of three reading strategies:

| Strategy | Meaning | Real-world analog |
|---|---|---|
| **A full** | every searchable text in the library (including subdirectories, excluding data directories and files > 2 MB) | "a new session reads all documents first" |
| **B legacy** | only `00` + `05` | the reading strategy recommended by v1 |
| **C current** | `kb-context.py` budgeted routing | the reading strategy recommended by v2 |

C's bar is not "smaller is better" but **small and no quality loss**. A beautiful compression ratio that drops a hard constraint is a net loss.

**Look primarily at C versus A.** A is the true cost of "read everything". Compared to B, C can be negative on small libraries, because C carries wrappers (`## [P0]` headings, `<!-- source -->`, selection reasons, gaps, pointers) while B is plain `00+05`. Selling "how much smaller C is than B" necessarily backfires on small libraries.

## 1. Reproduction

```bash
S="$HOME/.skills-manager/skills/handoff-kb/scripts"
py "$S/kb-benchmark.py" --target "[PROJECT_DIR]" --report markdown
py "$S/kb-benchmark.py" --target "[PROJECT_DIR]" --report json --budget 3000 --loose
```

- Dependencies: none. No network, no package install, no model call.
- `--budget`: the budget passed to `kb-context.py` (default 3000).
- `--loose`: mandatory for custom-naming projects (`60_进度.md` / `61_流水.md` / `60_流水/`).
- `--report json`: for CI and secondary statistics; fields in §5.
- Exit codes: quality gate passed → `0`; not passed → `1`; target is not a handoff library → `2`.

## 3. Ten quality metrics: 5 hard gates + 5 reported only

Metrics have two tiers, because freezing fixture-limited metrics at 100% only turns the test green; it does not improve quality.

**Must be 100% (any failure → exit code 1)**

| Metric | Pass condition |
|---|---|
| Hard constraints kept | every task has a P0 block (`dashboard.constraints` or the `AGENTS.md` hard-constraints section) |
| Wrong path rejected | a non-existent directory → exit code 2 with `ERR` on stderr |
| Budget honest | `used ≤ budget`, and `over_budget` matches reality (no false claims) |
| No silent workstream omission | `selected_lines` and `omitted_lines` do not intersect; omitted lines are explained in gaps |
| Tokenizer consistent | `requested` matches the tokenizer passed in, and `exact` matches actual capability |

**Reported only (recorded, does not block merging)**

| Metric | Pass condition |
|---|---|
| Target section hit | for `section_id` tasks, the expected `kb:id` appears in the returned blocks |
| Target fact hit | when asking about a fact by ID, the returned block contains that ID with a correct status judgement |
| Gaps reported honestly | `gap` / `gap_or_hit` tasks actually return non-empty `gaps` |
| Archive not mixed into default context | block `source` contains no root-level archive-role file (`90_*.md` / `*归档*.md`) |
| P4 bounded by count and budget | P4 blocks ≤3, P4 tokens ≤ 30% of budget, noise ratio not silently ignored |
| Duplicate loading | same-section and cross-section duplicates each counted once (by `text_sha`); same-section splits are not duplicates |

Quality gate (exit 0 only when all hold):

1. Gradeable tasks passed ≥ 80% (**rounded up**: with 10 tasks ≥8, with 8 tasks ≥7);
   do not use `round()` / half-up: `round(8*0.8)=6`, i.e. 75%, and the gate becomes a lie;
   prefer avoiding `math.ceil(total*0.8)` too: 0.8 is inexact in binary and every change in task
   count reopens "does a hair below count as rounding up". The implementation uses integer
   arithmetic `(total*4 + 4) // 5`, no floats.
2. Overall pass rate of the 10 metrics ≥ 80%;
3. **All 5 hard gates pass**.

Rule 3 exists to stop an average from hiding a fatal regression: one missing hard constraint or one accepted bad path must not be covered by a pretty 90% average.

**Workstream recall** is reported in three tiers: `full` (every line that should load did) / `partial` (loaded with omissions, stated) / `silent` (missed and unstated). Silent omission counts as a hard-gate failure.

**Gradeable tasks**: when the library has no `kb:id` at all (v1, not migrated), `section_id` tasks cannot be verified and are marked "skipped: no kb:id in an unmigrated library", excluded from the pass-rate denominator, with a reminder at the end of the report to run `kb-migrate.py`. Likewise, when the library has no superseded facts, "superseded must point to its replacement" is skipped — there is no object to test, not a correct answer. This is not leniency; it prevents "not tested" from impersonating "passed".

## 4. Where the token numbers come from

| tokenizer | Precision | When to use |
|---|---|---|
| `heuristic` (default) | estimate: CJK 1 char ≈ 1 token, other 4 chars ≈ 1 token | daily work, CI, cross-machine comparability |
| `tiktoken` (optional) | real BPE counting | external reporting, billing reconciliation |

A / B / C **use the same `TokenCounter` instance**: A and B via `counter.count(text)`, C via
`kb-context.py`'s `used` (the same counter internally), with the subprocess aligned through `--tokenizer`.
Earlier A/B went through `estimate()` while C took another path, so the numbers disagreed; that is fixed.

A missing `tiktoken` **never degrades silently**: requesting `--tokenizer cl100k_base` without an encoder
makes `kb-context.py` exit 2 and requires an explicit `--allow-tokenizer-fallback` (`exact: false` in the report).
`tests/deps_check.py` guarantees `scripts/` imports only the standard library plus the local `lib`; `tiktoken` is the only exception and must sit inside a function-level `try/except`.

## 5. JSON fields

```json
{
  "target": "...", "budget": 3000, "tokenizer": "heuristic…",
  "exact": false, "loose": false, "unmigrated": false,
  "tokens": {"A_all": 3082, "B_00_05": 389, "C_mean": 454.3, "C_error_paths": 1},
  "reduction_vs_A": 0.853,
  "reduction_vs_B": -0.168,
  "quality": {"passed": 10, "total": 10, "rate": 1.0},
  "metrics": {"constraint_kept": {"label": "硬约束保留", "passed": 9, "total": 9},
              "p4_bounded": {"label": "P4 受数量与预算约束", "passed": 9, "total": 9}},
  "metrics_rate": 1.0,
  "recall": {"full": 1, "partial": 0, "silent": 0},
  "gate": {"min_rate": 0.8, "min_passes": 8,
           "must_pass": ["constraint_kept", "error_rejected", "budget_honest",
                         "lines_honest", "tokenizer_consistent"],
           "hard_ok": true, "passed": true},
  "rows": [{"id": 1, "title": "...", "a": 3082, "b": 389, "c": 329,
            "noise": 0.0, "counted": true, "graded": true,
            "quality": "hit dashboard.current", "pass": true, "ms": 164}],
  "files": [{"path": "00_基线.md", "tokens": 98}],
  "notes": ["..."]
}
```

- `counted`: participates in the C mean. Error paths are `false`.
- `graded`: participates in the pass rate. Section tasks in unmigrated libraries, or tasks whose status fact is absent, are `false`.
- Keys inside `metrics` are stable; `gate.must_pass` lists the 5 items that must be 100% in this version — **never quote `metrics_rate` alone as the conclusion**.
- `recall`: full / partial / silent counts for multi-workstream recall; `silent > 0` always comes with `gate.passed = false`.
- `duplicates`: `exact` (same position, same content: assembly-level double loading) / `cross` (same text elsewhere, usually a symlink or container fallback collision) / `split_sections` (one section split into several blocks, by design). Reported only, not gated; when `exact > 0`, inspect the assembly layer first.
- `ms` is the process start plus computation for one `kb-context.py` call, including interpreter startup; it is **not** an algorithmic complexity measure.

## 6. Three data sources: do not mix them

| Source | May claim | May not claim |
|---|---|---|
| Synthetic fixture (`make_fixture`) | ratios between the three strategies, all 10 metrics passing, wrong paths rejected | "saves 85% of tokens" as a product metric |
| Anonymized FFRS fixture (`--loose`) | custom naming (`60_进度.md` / `60_流水/`) also routes | that it represents a real project's size |
| Real project (own library, read-only) | "in my library, handoff dropped from X to Y tokens with this task set" | generalizing to "every project saves Y%" |

**Anonymized FFRS fixture** (`tests/fixtures/ffrs/`, all content fictional, `--loose`):

| Metric | Value |
|---|---|
| A full | 1,248 tokens |
| B `00+05` | 446 tokens |
| C routing (budget 3000, 9 tasks) | 513 tokens |
| C versus A | −58.9% |
| C versus B | −14.9% (larger) |
| Tasks / quality items | 10/10, 63/63 (all 5 hard gates) |
| Workstream recall | full 1 / partial 0 / silent 0 |
| Duplicate loading | same-section 0 / cross-section 0 (49 blocks; 3 same-section splits by design) |

**Real library, read-only observation** (FFRS, 2026-11-11; both `kb-check` and `kb-benchmark` are read-only):

| Metric | Value |
|---|---|
| A full | 1,747,096 tokens (including large asset and backup directories) |
| B `00+05` | 4,866 tokens |
| C routing (budget 3000, 2 gradeable tasks) | 1,768 tokens |
| C versus A | −99.9% |
| C versus B | +63.7% (larger) |
| Gradeable tasks | 1/3 passed (the other 7 marked "skipped": 6 lacked `kb:id` or the corresponding status fact, 1 had only one workstream) |
| Quality items | 13/15 (87%); the failures were the **hard gate** "hard constraints kept" 0/2 |
| Workstream recall | full 0 / partial 0 / silent 0 (that library has one line; task 10 skipped) |
| Quality gate | **not passed** (`hard_ok: false`) |

This is exactly what the benchmark should do: **it did not treat "saved 99.9%" as success**; it pointed out that the library declares hard constraints nowhere, cannot be tested by section routing (0 `kb:id`), and has 36 facts without any status (valid 0 / unverified 0 / superseded 0 / unknown 36). The fix is to add a constraints section, give facts statuses and run `kb-migrate.py --plan` — not to tune parameters.

In the same library, `kb-check --loose` numbering diagnostics went from **ERR 4 → ERR 0**: the "unverified" list in `00_INDEX.md` held 4 `- G-0xx：…` navigation lines that collided with the shards' real definitions; they are now treated as index-page pointers (rule in SKILL.md §6), and `kb-context --task "G-011 现在还算数吗"` verified that the P3 block source moved from the index page to `10_游戏事实.md`.

### 6.1 Retractions: "C = 89 tokens / 77% saved" in the 2.0 docs and "C = 395.6" in 2.0.1

- **89 tokens**: produced by a defective `kb-context.build()` that never queued P2 into assembly — fewer blocks meant a smaller number, which was written up as "very economical".
- **395.6 / 1,886**: the task set changed from "find a fact / trace evidence / resolve conflicting knowledge" to "locate a fact by ID / point a superseded fact to its replacement / flag unverified facts", and metrics went from 8 to 10. The definition changed, the numbers are no longer comparable, and **they have been removed from README and this file**.

The reasoning is simple: `used` was 89 while the P0+P1 wrappers alone exceed that. The current implementation 1) actually assembles P2, 2) converges the budget on the **final rendering**, 3) writes lines that do not fit into `omitted_lines` and gaps. Better a larger number than recording "under-delivered" as "saved".

### 6.2 2.0.1 → 2.0.2 across three libraries (read-only, same task set)

Same tasks, same budget (3000), same tokenizer definition, one run per version (2.0.1 = `main` at `b524c56`; 2.0.2 = `fix/2.0.2-gate-summary`). All three libraries live under `H:\AI工作区`, read-only, no file modified.

| Library | Tasks | 2.0.1 `used` total | 2.0.2 `used` total | Change |
|---|---|---|---|---|
| 求职261104 | 4 | 5,242 | 4,925 | −317 (−6.0%) |
| 路由器和网络 | 6 | 16,101 | 15,888 | −213 (−1.3%) |
| FFRS | 5 | 7,976 | 8,737 | **+761 (+9.5%)** |

FFRS became more expensive because **what got loaded changed**, not because wrappers grew:

| Task | What P4 dropped | What P4 picked up |
|---|---|---|
| 机械冲撞伤害怎么算 | `.shared/memory/2026-11-12.md` (knowledge-base rework log) | `10_游戏事实.md` G-001 / G-017 / common misjudgements (3 sections) |
| 幻兵培养表怎么更新 | `.shared/memory/2026-11-12.md` | `10_游戏事实.md` G-010 |
| 解包数据在哪里 | `.shared/memory/2026-11-08.md` | `20_数据与解包.md` D-011 + `30_mod开发.md` M-008 |
| 磁盘写满怎么办 (router library) | `.workbuddy/memory/2026-11-07.md` | `xray-hy_磁盘写满事故报告_20261107.md` |

At the same time `gaps` lost 2 entries per task (phantom P0 gaps withdrawn) and the P4 gap became a boundary statement (~55 tokens per task); the rest of the increase is real shard body. Saving tokens is not the only goal: replacing "what happened on some day" from `.shared/memory` with game facts costs 9.5% more and is a net gain.

Do **not** compare `kb-benchmark`'s own A/B/C means across versions; two definitions changed:

- **A's corpus changed**: since 2.0.2, 15 client directories such as `.workbuddy` / `.shared` are not body text, so A dropped from 281,420 to 211,569 for the router library and from 1,756,150 to 1,733,275 for FFRS. That is "no longer counting what should not count", not a smaller library.
- **C's denominator changed**: FFRS gradeable tasks went from 8 to 9 — after the phantom-P0 fix, one task previously skipped for "no hard constraints found" became gradeable. Different denominators mean the means are incomparable, which is why the table above uses the **`used` totals of the same task set**.

Quality did not regress: all three libraries pass the hard gates (`hard_ok: true`) with 6/6, 5/5 and 9/9 quality items (all 100%); FFRS workstream recall moved from `full 0 / partial 0 / silent 0` to `0 / 1 / 0` — finally one task graded as "partial recall, stated" instead of "nothing recalled, nothing said".

## 7. What this benchmark does not measure

- **Whether answers are correct**: it only checks whether the right passages entered the context, not the model's reasoning afterwards.
- **Multi-turn dialogue**: single-turn tasks, no follow-ups, corrections or context accumulation.
- **Write quality**: `kb-write.py` correctness is covered by `tests/test_write.py` / `test_transaction.py`, not here.
- **Latency and cost**: `ms` includes process start; real API latency and billing are not linear in token count.
- **Extreme libraries**: libraries > 10 MB or > 500 files have not been stress-tested; `kb-context.py` has a P4 cap, but search still scans the whole library.

## 8. When changing this script

- The task set is a **contract**: adding or removing tasks requires updating the table in §2 and the numbers in README, otherwise the documentation starts lying.
- Do not loosen the criteria: `section_id` tasks must verify P0 as well, otherwise "drop the hard constraints for a lower token count" can game the score.
- Do not tune `--budget` to make the reduction look good; the budget should follow the consuming model's context window, not the benchmark.
- For a new metric, decide first whether it is pass/fail or diagnostic; mixing diagnostics into the pass line turns the script into a tuning game.
- The archive metric may only be compared against **root-level archive-role files**: block `source` is a file name, so comparing against "all names under the archive directory" produces false positives whenever `归档/` contains a whole-library backup (this actually false-flagged 5/9 on FFRS once).
