# handoff-kb

**给多会话并行项目的分层交接库。** 一套文件约定 + 三个零依赖 Python 脚本：让「上下文快满、几条线同时推、文档越堆越多」的项目，在新会话接手时只读固定的一小份（约 4.5k tokens），而不是全库重读（约 49k）。

不是笔记软件，不是向量库。是**人工 RAG + 分层 wiki**：靠文件名、章节号、编号 ID 做路由，纯文本、可 diff、零运行时依赖，agent 不用任何工具就能读。

---

## 它解决的问题（是算术，不是文风）

中文 UTF-8 约 4.5 字节 / token。项目文档总量 S 越大，新会话「全读一遍」的代价就越荒谬：

```
接手成本 ≈ S / 4.5
S = 221 KB  →  ≈ 49k tokens，一上来烧掉三分之一上下文
```

而**真正决定接手质量的信息**（现在在干嘛、下一手、别做什么）通常不到 20 KB。所以答案不是「把文档写薄」，而是**把「存」和「读」解耦**：总量可以一直涨，单次必读集合恒定在三份以内。

实测（一个路由器固件项目）：

| | 改造前 | 改造后 |
|---|---|---|
| 全库 | 1,759 行 / 221 KB | 总行数反而涨了（过程被归档而非删除） |
| 接手必读 | 全库 221 KB ≈ 49k tokens | `05` + `00` = 20.6 KB ≈ 4.5k tokens，**降 90%** |

## 分层模型

| 层 | 文件 | 放什么 | 改动频率 | 接手必读 |
|---|---|---|---|---|
| L0 入口 | `AGENTS.md`（+ `CLAUDE.md` / `GEMINI.md` 两行指针） | 读哪份、怎么写。**绝不写当前值** | 极少 | 读（3 KB） |
| L1 事实 | `00` 共享页 + `01`–`0N` 按线分册 | 当前值 / 不变量 / 判据 / 命令 / 坑与结论 | 少 | 按线读 |
| L2 现状 | `05_进度仪表盘.md` | 各线状态 + 待办 + 交叉点 + 接手顺序 | 常改 | **必读** |
| L3 流水 | `06_会话日志.md`（历史卷只读）+ `06_流水/<线>.md` | append-only 时间线 | 按线只写自己那份 | 追溯才读 |
| L4 归档 | `90_过程档案.md` + `归档/` | 过程证据 / 验证快照 / 版本考古 | 折叠时才写 | 非必读 |

两条硬约束：

- **编号是契约**：`00` 的 `K-xx`、结论索引 `G-xxx`、事实层 `§1–§9`、归档 `§A–§G`；改内容可以，**别重排、别复用已作废的 ID**。
- **一写者一文件**：多个会话并行时，`06_流水/<线>.md` 分片从根上消除「读-改-写」覆盖；冲突信号靠 `git status`，不靠纪律。

## 快速上手

### 1. 先判断该不该用

| 你的情况 | 怎么办 |
|---|---|
| 单会话、任务做完传给下一个会话、只要一份交接说明 | 别用这套，写 6 行 handoff |
| 文档 < 3 份、没有并行会话、一次性任务 | 别用这套 |
| 多条线 + 多会话并行 + 上下文容易满 + 长期维护 | 用，从 `kb-init.py` 开始 |
| 老项目已有一堆文档要整理成库 | 用，走「存量改造」 |

简单 handoff 模板（贴进新会话即可，不落盘、不建库）：

```text
接手 [任务]，工作目录 [DIR]。
已完成：[1–2 行]
进行中 / 卡点：[1 行]
下一手：[1 行]
相关文件 / 提交：[路径 或 git log -3]
别重复踩：[1 行，没有就删]
```

### 2. 从零搭（一键脚手架）

```bash
SKILL="$HOME/.skills-manager/skills/handoff-kb"   # 换成你的实际安装目录
py "$SKILL/scripts/kb-init.py" \
    --target "~/projects/新项目" \
    --project "新项目" \
    --lines "固件,运行态,服务端,测速"
```

生成 `AGENTS.md` / `CLAUDE.md` / `GEMINI.md`、`00_基线.md`、`01..0N` 分册、`05_进度仪表盘.md`、`06_会话日志.md` + `06_流水/*.md` 分片、`90_过程档案.md`、启动消息、`.gitignore` / `.gitattributes`、自检脚本占位、`归档/`，并自动 `git init -b main` + 首次 commit + 除密扫描 + 接手成本估算。

```text
--no-git              只生成文件
--force               覆盖同名模板（默认跳过）
--shards auto|none    auto=按 --lines 生成 06_流水/ 分片（默认）；none=单份 06_会话日志.md
```

### 3. 只读体检

```bash
py "$SKILL/scripts/kb-check.py" --target "~/projects/新项目"
py "$SKILL/scripts/kb-check.py" --target . --strict              # WARN 也算失败
py "$SKILL/scripts/kb-check.py" --target "~/projects/老项目" --loose   # 自有命名体系
```

输出：各层体积与接手成本估算、阈值命中、残留 TODO / 明文凭证、`K-xx`/`G-xxx` 编号重复、Markdown 表格列数一致、git 未提交改动与最近 5 条 log。ERROR > 0 退出码 1。

`--loose` 给**已有自己命名体系**的项目用（`60_进度.md` / `00_INDEX.md` / `HANDOFF.md` 一类）：必需文件名缺失只报 WARN，其余照跑——不用先改造就能拿到体检报告。别名识别：`*进度*`/`*现状*` → 现状层，`*INDEX*`/`*索引*` → 基线，`*流水*`/`*日志*` → 流水。

体积统计自动跳过 `AI_files/` / `assets/` / `data/` / `output/` / `evidence/` / `node_modules/` / `build/` 等资料目录与 >2 MB 文本，避免解包数据把接手成本比例压成 0。

### 4. 大文档分段读

几百行的参考手册别整份塞进上下文，先拿目录树与 `source-hash`，再按节读：

```bash
S="$HOME/.skills-manager/skills/handoff-kb/scripts/kb-outline.py"
py "$S" --file 03_服务端_精简交接.md                          # 目录树：#N / 行号 / 节行数 / hash
py "$S" --file 03_服务端_精简交接.md --find 磁盘               # 只列标题含关键词的节
py "$S" --file 03_服务端_精简交接.md --section 21 --hash 1ff381af139d
py "$S" --file 03_服务端_精简交接.md --section 11 --max-lines 80 --offset 0   # 分段续读
```

`--hash` 传了就校验：文档变了会拒绝读取并退出 2，防止按过期目录取到错节。`--no-children` 只取本节正文；跳过代码围栏里的 `#` 行；行号可直接写成 `文档 §X` 引用。

## 存量项目改造（五步，别跳步）

完整手册 `references/migration.md`：只读诊断 → 五步逐步展开（目标 / 判据 / 命令 / 产物 / 坑）→ 验收 → 回滚 → 真实案例。给新会话开任务直接贴 `assets/migration-prompt.txt`。

1. **`git init`** —— 先写 `.gitignore`（凭证 / 日志 / 大二进制）再 `add`。没有版本控制，后面任何拆分都无法回滚。
2. **过程下沉** —— 历史矛盾、验证快照、版本考古搬进 `90 §A–§G`，主文档只留 `详见 90 §X`。**只删过程，坑与结论一条不留地保留**。
3. **建 `05`** —— 把散落各处的状态 / 待办抽到一处，删掉同源重复副本。
4. **拆 `06`** —— 单条 >3 行或 `05` 涨到 ~70 行才拆；搬运用 `sed -n 'Np' >> 06` + `cmp` 校验，别手抄。
5. **加机制** —— 入口、K-xx 编号与状态列、阈值表、收尾 commit 规则最后补。

**别提前拆**：进度文件只有 30 行时拆成两份，反而要翻两份。

## 阈值表（触线才动手）

| 对象 | 阈值 | 动作 |
|---|---|---|
| `05` §0 现状 | > 4 行 | 压缩，细节进 `06` |
| `05` §6 摘要 | > 5 条 / 单条 > 3 行 | 整条移进 `06` |
| `06` 流水（单分片） | > 200 行 或 > 60 KB | 该分片折叠进 `90`，只留标题 + 指针 |
| `00` 基线 | > 150 行 | 升级成结论索引（K-xx + 状态列） |
| `90` 归档 | > 600 行 | 再分卷或移 `归档/` |
| 事实层分册 | > 8 个 | 按领域合并，别继续加编号 |

## 反模式（全是踩过的）

| 坑 | 后果 |
|---|---|
| 长话术三份同源 | 改一处漏两处，口径漂移 |
| 500 行参考手册列进「接手必读」 | 每个新会话白烧几十 k token |
| `05` 堆已完成的待办 | 待办区被历史稀释，看不到下一手 |
| 删过程时连坑一起删 | 下次重走旧路 |
| 明文密码 / AK 直接 `git init` | 凭证永久进历史，删不掉 |
| 大视频没排除就 `add` | 仓库瞬间几十 MB，历史不可清 |
| 无 git 时并发改共享文档 | 后写者全胜且无提示 |
| 重排 §编号 / 复用 K-xx ID | 全库引用失效 |
| 整文件覆盖写 `05` | 抹掉别的会话刚追加的行 |

清理原则一句话：**只删「已结案背景 / 过程性时间戳 / 验证快照」，保留「当前基线 / 配置 / 踩过的坑 / 结论 / 命令参考」**。

## 安装

真实目录只有一份，客户端目录用软链 / junction 指过来即可（Windows `mklink /J`、Linux/macOS `ln -s`）：

```text
~/.skills-manager/skills/handoff-kb      ← 真实目录（本仓库）
<项目>/.workbuddy/skills/handoff-kb      → 软链
<项目>/.codex/skills/handoff-kb          → 软链
<项目>/.claude/skills/handoff-kb         → 软链
```

Windows 下真实目录形如 `C:\Users\<你>\.skills-manager\skills\handoff-kb`，Git Bash 里写成 `$HOME/.skills-manager/skills/handoff-kb`。

技能清单见 `SKILL.md`（含适用边界、分层模型、SOP、阈值、反模式、验收四问）；`references/protocol.md` 是可整段贴进项目 `AGENTS.md` 的可移植契约。

## 文件

```text
SKILL.md                  技能主体（判定 → 建库 → 改造 → 体检 → 分段读 → 验收）
references/protocol.md    设计原理 / 并发模型 / 可移植契约
references/migration.md   存量改造完整手册（诊断 → 五步 → 验收 → 回滚 → 案例）
assets/                   11 个骨架模板（AGENTS / 00 / 事实层 / 05 / 06 单卷与分片 / 90 / 启动消息 / git 配置）
assets/migration-prompt.txt  老项目改造启动话术，填空即可交付给新会话
scripts/kb-init.py        一键脚手架 + git init + 除密扫描 + 接手成本估算
scripts/kb-check.py       只读体检（--loose 兼容自有命名体系）
scripts/kb-outline.py     Markdown 目录树 + 按节读 + source-hash 重验证
```

## 天花板

这套结构靠人工路由，没有 embedding / 语义检索 / 并发锁。出现下列信号该升级而不是继续加文档：

- 需要「问一句话命中段落」而不是「知道去哪份翻」→ 加语义检索层。
- `00` 超过 150 行且 `K-xx` 超 30 条 → 结论索引独立成册。
- 并发会话长期 >3 个且频繁冲突 → 上锁或把 `05` 按线分片。
